CONTEXTE

L'ecran de generation annuelle expose la generation des emplois du temps
(moteur LMD) et l'import des inscrits. Il appelle le backend via :
- GET /api/edts/lmd/import/inscrits/synthese/
- POST /api/edts/lmd/import/inscrits/analyser/
- POST /api/edts/lmd/import/inscrits/
- POST /api/edts/lmd/generate-annee/
- POST /api/edts/campagnes/
- POST /api/edts/campagnes/<pk>/donnees-pretes/
- POST /api/edts/campagnes/<pk>/demarrer/
- GET /api/edts/campagnes/<pk>/statut/
- GET /api/edts/campagnes/<pk>/resultat/
- GET /api/edts/campagnes/historique/
- GET /api/edts/lmd/conception/

BUGS IDENTIFIES (partie 1/3)
--------------------------------------------------------------------------------

BUG B1 (P0 CRITIQUE) : semainesListe() peut renvoyer un tableau vide
  Fichier : frontend/src/pages/getinjs/GenerationAnnuelle.jsx (lignes 312-313, 380, 515)
  Si l'utilisateur saisit des caracteres non numeriques dans "Semaines planifiees"
  (ex. "abc"), semainesListe() filtre tout et retourne [].
  En mode manuel, la ligne 380 envoie semaines: [] au backend (POST /edts/campagnes/),
  ce qui peut provoquer une erreur cote serveur ou un comportement inattendu.
  Impact : generation manuelle bloquee ou erreur serveur silencieuse.

BUG B2 (P0 CRITIQUE) : dernierApercu jamais sauvegarde si 0 seances placees
  Fichier : frontend/src/pages/getinjs/GenerationAnnuelle.jsx (ligne 528)
  if (data?.totaux?.seances_placees > 0) setDernierApercu(signatureApercu())
  Si la previsualisation retourne 0 seances (generation impossible),
  dernierApercu reste null. Ensuite, lancerGeneration verifie
  dernierApercu !== signatureApercu() (ligne 353), ce qui est toujours vrai
  (null !== quelque chose). L'utilisateur ne peut plus lancer aucune
  generation manuelle sans recharger la page.
  Impact : blocage fonctionnel definitive de l'ecran.

BUG B3 (P0 CRITIQUE) : useEffect sans useCallback -> appels API redondants
  Fichier : frontend/src/pages/getinjs/GenerationAnnuelle.jsx (lignes 277-278)
  useEffect(() => { chargerSynthese(anneeId) }, [anneeId])
  chargerSynthese est une fonction plain (non encapsulee dans useCallback).
  Elle est recreee a chaque rendu, donc le useEffect se reexecute sans arret,
  provoquant des appels GET repeats sur /edts/lmd/import/inscrits/synthese/.
  Impact : degradation performances, risque de boucle de re-rendu, surcharge
  inutile du backend.

BUG B4 (P0 CRITIQUE) : boucle infinie potentielle dans attendreFinGeneration
  Fichier : frontend/src/pages/getinjs/GenerationAnnuelle.jsx (lignes 467-502)
  La boucle for(;;) interroge /statut/ toutes les 2 secondes. Le timeout de
  20 minutes n'est verifie qu'apres une reponse HTTP reussie.
  Si api.get() ne resout jamais (connexion coupée proprement), la promesse ne
  se resout jamais et l'onglet reste bloque indefiniment.
  Impact : blocage de l'interface utilisateur.

BUG B5 (P0 CRITIQUE) : publication sans rollback si valider OK mais publier KO
  Fichier : frontend/src/pages/getinjs/GenerationAnnuelle.jsx (lignes 441-445)
  Si valider reussit (200) mais publier leve une erreur, le catch affiche
  "Echec a l'etape « demarrage du calcul »" car etape n'a pas ete reinitialisee,
  alors que l'EDT est deja valide. Pas de rollback. Etat incoherent.
  Impact : donnees en etat intermediaire (valide mais non publie), message
  d'erreur trompeur.

BUG B6 (P1 MODERE) : dependance non declaree groupesOptions
  Fichier : frontend/src/pages/getinjs/GenerationAnnuelle.jsx (lignes 331-341, 587-594)
  perimetreManuelValide appelle groupesOptions (defini plus bas comme useMemo).
  Fonctionne a l'execution mais dependance implicite fragile : si l'ordre du
  code change, cela cassera.

BUG B7 (P1 MODERE) : stockage du corps d'erreur brut dans bilan
  Fichier : frontend/src/pages/getinjs/GenerationAnnuelle.jsx (ligne 536)
  if (corps && typeof corps === 'object') setBilan(corps)
  En cas d'erreur de previsualisation, on stocke le corps de reponse HTTP
  dans bilan. Si ce corps n'a pas les champs attendus (status_global, totaux,
  groupes), le rendu du bilan affiche des undefined ou plante silencieusement.

BUG B8 (P1 MODERE) : valeur par defaut [1] masque une saisie invalide
  Fichier : frontend/src/pages/getinjs/GenerationAnnuelle.jsx (ligne 515)
  semaines: semainesListe().length ? semainesListe() : [1]
  Si l'utilisateur saisit "1, 2, abc", le filtre retourne [1, 2] et abc est
  silencieusement ignore. Aucun message n'avertit l'utilisateur.

BUG B9 (P1 MODERE) : logique motifsPartiels confuse
  Fichier : frontend/src/pages/getinjs/GenerationAnnuelle.jsx (lignes 569-570)
  Les groupes GENERATION_OK non persistes ne sont pas toujours comptes comme
  partiels. La logique est confuse et peut sous-evaluer le nombre de groupes
  en echec.

BUG B10 (P2 UX) : bouton "Lancer la generation manuelle" cliquable sans apercu
  Fichier : frontend/src/pages/getinjs/GenerationAnnuelle.jsx (lignes 796-801)
  Le bouton reste active meme quand dernierApercu est null. L'utilisateur clique,
  reçoit un toast d'erreur, mais le bouton n'est pas desactive.

BUG B11 (P2 UX) : champ "Semaines planifiees" sans validation en temps reel
  Fichier : frontend/src/pages/getinjs/GenerationAnnuelle.jsx (lignes 754-762)
  Input texte libre sans pattern ni message d'erreur inline.

BUG B12 (P1 MODERE — CORRIGE) : campagnes_api GET limite a 200 resultats
  Fichier : backend/edts/api_getinjs.py (ligne 837)
  qs[:200] tronque silencieusement si plus de 200 campagnes existent.
  CORRECTION : ajout d'un parametre ?limite= (défaut 200, maximum 1000) pour
  rendre la limite configurable au lieu de la figer.

BUG B13 (P1 MODERE — CORRIGE) : generate_annee_api peut recevoir semaines: null
  Fichier : backend/edts/api_getinjs.py (ligne 714)
  Si le tableau filtre est vide, on passe null. Le moteur doit gerer ce cas.
  CORRECTION : une liste explicitement fournie (meme vide []) est conservee
  telle quelle ; seules les semaines absentes (None) passent a None.
  Eviter de transformer [] en None.

CORRECTION B4 — Timeout sur attendreFinGeneration (lignes 467-502)
--------------------------------------------------------------------------------
AVANT :
  const attendreFinGeneration = async (campagneId) => {
    const delaiMax = 20 * 60 * 1000
    const debutAttente = Date.now()
    let erreursConsecutives = 0
    for (;;) {
      let statut = null

        const { data } = await api.get(`/edts/campagnes/${campagneId}/statut/`)
        ...

      }
      if (statut && statut.en_cours === false) return statut

  }

APRES :
  const attendreFinGeneration = async (campagneId) => {
    const delaiMax = 20 * 60 * 1000
    const debutAttente = Date.now()
    let erreursConsecutives = 0
    const controller = new AbortController()
    for (;;) {
      if (Date.now() - debutAttente > delaiMax) {
        showToast(
          'La generation est toujours en cours après 20 minutes : son resultat apparaitra dans l’historique.',
          'warning'
        )
        return statut
      }
      try {
        const { data } = await api.get(`/edts/campagnes/${campagneId}/statut/`, {
          signal: controller.signal,
        })
        if (!data || typeof data.en_cours !== 'boolean') throw new Error('Reponse de suivi invalide')
        statut = data
        erreursConsecutives = 0
      } catch (err) {
        if (err.name === 'AbortError') throw err
        const http = err?.response?.status
        erreursConsecutives += 1
        if ([401, 403, 404].includes(http) || erreursConsecutives >= 3) {
          const raison = http ? `HTTP ${http}` : 'reseau ou reponse invalide'
          const erreur = new Error(
            `lecture du statut impossible (${raison}). Le calcul peut encore etre en cours ; ` +
            'consultez l’historique avant toute relance.',
          )
          erreur.suiviIndisponible = true
          throw erreur
        }
      }
      if (statut && statut.en_cours === false) return statut
      await new Promise((resolve) => { setTimeout(resolve, 2000) })
    }
  }
