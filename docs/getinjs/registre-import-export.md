# Registre Étudiants — imports et exports

La page **Étudiants** exporte le registre filtré (toutes les pages) en PDF, Excel de lecture (une feuille par groupe), Word et CSV UTF-8 avec séparateur `;` et en-tête. Les permissions et le périmètre du secrétariat s'appliquent côté serveur, pas seulement aux boutons.

Le **CSV exporté** est le modèle réimportable. Pour un import XLSX, utiliser un onglet `Participants` avec une ligne d'en-tête `matricule`, `nom`, `prenom` et éventuellement `sexe`, `date_naissance`, `lieu_naissance`, `email`, `telephone`, `telephone2`, `type_concours`, `libelle_concours`, `categorie`, `grade`, `groupe`, `grade_groupe`, `vague`, `site`, `salle`. Les numéros de matricule et de téléphone doivent être au **format texte** dans Excel pour préserver les zéros initiaux. Le fichier Excel de **liste de classe** est un document de lecture et ne constitue pas ce modèle d'import.

L'import du registre est réservé aux comptes autorisés à ajouter des étudiants et habilités par l'API. Limites : CSV ou XLSX, 20 Mo et 10 000 lignes. Le matricule, le nom et le prénom sont obligatoires ; un matricule répété dans le fichier, une ligne vide suivie d'autres données ou une erreur de validation annule **tout** le lot. Les matricules existants sont mis à jour ; les autres sont créés. Les champs optionnels absents ou vides ne suppriment pas les valeurs déjà enregistrées. Cet import **n'inscrit pas automatiquement aux modules ni aux parcours LMD** : ces opérations sont distinctes. Vérifier le nombre de créations/mises à jour et les affiliations après import, idéalement sur une copie de recette avant production. Conserver une sauvegarde de la base réellement servie avant un import massif.

Le code est fourni dans la branche Arena courante, pas installé automatiquement sur `injs.badge-qr-code.pro`. Le paquet source et les images de l'ancien SHA `f5e4259` ne comportent **pas** ces modifications : reconstruire les deux images depuis le nouveau code et utiliser son SHA exact lors du déploiement local Mac → VPS.
